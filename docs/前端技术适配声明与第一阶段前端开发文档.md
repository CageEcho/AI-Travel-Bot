# 第一部分 · 前端技术适配声明

## 1. 项目判断
- 产品类型：B 端内部工具，AI 行程方案生成工作台（多轮对话 + 分阶段确认 + 结构化产物）
- 主要用户：高端旅行顾问（桌面办公为主）
- 主要终端：桌面 Web（1280 / 1440）为主；移动 Web（390 / 768）基本可用
- 新项目或已有项目：**新项目**。后端 M0 已完成并带一个单文件验收界面 `backend/app/static/index.html`（临时验收工具，保留作兜底）
- 本阶段业务目标：顾问在正式前端里走完「粘贴原话 → 需求卡确认 → 生成 → 查看方案/成本/待核实」的完整闭环，刷新后可恢复

## 2. 输入资料
- PRD：已读取（v2 设计依据、v3 实施规格）
- 后端手册与后端阶段文档：已读取；后端代码已在本仓库
- 接口文档：**完整**（10 个接口，Pydantic 结构即契约）
- 设计稿：无 → 采用中性方案（见第 5 节视觉方向），先出代表页
- 现有前端代码：仅单文件验收界面，作为交互参考

## 3. 技术选择
- 框架与版本：Next.js 16（App Router）+ React 19 + TypeScript strict；Node 24 / npm。依赖锁定在 `frontend/package-lock.json`
- 样式与组件策略：Tailwind CSS 4 + CSS 语义变量（`@theme`）；Lucide 图标；原生 HTML + 轻量自建组件（Button / Badge / Card / Tabs / Dialog），不引入组件库（对话框仅 1 个，用原生 `<dialog>`）
- 数据请求与状态策略：集中式 API 层（`lib/api/client.ts`）+ 手写类型与错误归一化；React 自带状态；**不引入** TanStack Query / Zustand（单页工作台、无跨页共享缓存）
- 流式通信策略：**轮询**（后端设计即提交 + 轮询，2s 间隔，页面不可见时暂停，完成/失败即停）；不用 SSE
- 表单方案：原生受控表单；槽位编辑用 Dialog；不引入 RHF/Zod（字段少、校验在后端）
- 测试方案：Vitest + React Testing Library（状态映射、错误归一化、槽位格式化、组件状态）；Playwright 一条核心闭环 E2E
- 部署环境：本地开发；`next.config` 用 `rewrites` 把 `/api/*` 同源代理到 `BACKEND_URL`（默认 `http://localhost:8000`，构建时注入）；`output: "standalone"`

## 4. Agent 状态
- 后端状态 → 前端统一状态映射（`lib/api/task-state.ts`）：
  `queued→queued`；`searching|planning|validating|costing→running`（带阶段标签与进度）；`done→succeeded`；`failed→failed`（`error.code=ORPHANED` 单独文案：服务重启导致中断，请重新生成）；未知值 → `stale`（重新拉取，不当成功或失败）
- 等待用户确认方式：**人工节点①**——需求卡完整度 ≥85% 才可「确认需求卡并生成方案」；追问以选项按钮呈现在对话流中；生成按钮点击后立即进入 `submitting`，防重复
- 取消、重试、断线恢复：后端无取消能力 → 不提供「取消任务」，只提供「停止等待」；失败可「重新生成」；轮询请求失败 3 次后进入 `disconnected` 并退避重试
- 任务 ID 与恢复入口：URL `/c/[convId]?plan=PLN-xxx&tab=plan`；刷新后按 convId 拉需求卡、按 plan 拉状态与版本，不依赖内存

## 5. 页面与产物
- 核心页面：`/`（新建/进入会话）、`/c/[convId]`（三栏工作台：对话 / 需求卡 / 方案面板）、`/search`（手动检索，LLM 不可用时的降级路径）
- 核心业务闭环：粘贴原话 → 看到槽位与角标 → 回答追问 → 确认并生成 → 分阶段进度 → 7 天行程 + 成本 + 待核实清单 → 刷新仍可见
- 产物类型和预览方式：结构化 JSON 产物（行程 / 成本 / 违规 / 待核实 / 轨迹），以卡片与表格渲染；ⓘ 溯源用 Popover；无多媒体产物
- 响应式目标：≥1024px 三栏；<1024px 单栏 + 底部三段切换（对话 / 需求卡 / 方案）
- 视觉方向（无设计稿的中性方案）：暖灰底 + 墨绿主色（延续验收界面），Inter + 系统中文字体；8px 节奏；卡片圆角 12px；四态角标用颜色 + 文字双编码

## 6. 偏离本手册的地方
- 偏离 1：不引入 TanStack Query / Zustand / RHF —— 单工作台、状态少，React 自带能力够用；复杂度出现再引入
- 偏离 2：不用 SSE —— 后端产物是整份结构化方案，中间片段无价值（后端适配声明「暂缓 2」）
- 偏离 3：保留 `backend/app/static/index.html` —— 作为 API 冒烟与兜底，不再新增功能
- 与后端阶段文档的关系：后端文档把 Next.js 前端「暂缓到 M2」，理由是先验证核心链路。核心链路已在 M0 验证通过（68 单测、评测 dry-run 全绿），本阶段按产品经理要求提前进入正式前端，属于产品经理本轮明确目标（手册第 3 节优先级第 1 条）

## 7. 待确认事项
- 真实模型 Key 尚未提供：对话抽取在前端会显示后端返回的 `LLM_FAILED` 友好错误；槽位可手动编辑走完闭环。拿到 Key 后无需改前端
- 是否需要多顾问登录（后端 M0 单用户）：本阶段不做鉴权

# 第二部分 · 第一阶段前端开发文档

## 1. 本阶段目标
顾问在正式前端里，把一段客户原话变成一份可查看溯源与成本的 7 天行程方案，刷新页面后方案仍在。

## 2. 范围
### 本阶段包含
- 页面：`/`、`/c/[convId]`、`/search`、`error.tsx`、`loading.tsx`、`not-found`
- 组件：AppShell（顶栏 + 移动端底部切换）、ChatPanel、RequirementCardPanel（SlotRow / SlotEditDialog / ConflictList / CompletenessBar）、PlanPanel（TaskProgress / DayCard / ItemRow / ProvenancePopover / CostView / ChecklistView / TraceView）、ui（Button / Badge / Card / Tabs / Dialog / Alert / Skeleton）
- 接口：全部 10 个 `/api/v1` 接口
- 任务状态：idle / submitting / queued / running(searching→costing) / succeeded / failed(含 ORPHANED) / disconnected / stale
- 产物：RenderedPlan / CostSummary / Violation / Checklist / Trace

### 本阶段不包含
- 拖拽调序、锁定、版本 diff、资源替换、导出（M2）
- 登录与权限、多会话列表（会话只靠 URL 恢复，最近会话记在 Local Storage 作为便捷入口，不冒充服务端数据）
- 向量检索相关界面（M1）

## 3. 用户流程
1. 打开 `/` → 「新建会话」→ 跳转 `/c/[convId]`
2. 粘贴客户原话 → 发送 → 需求卡出现槽位与角标；对话流出现 ≤3 个追问（带选项）
3. 点选项或手动编辑槽位 → 完整度上升 → 「确认需求卡并生成方案」可点
4. 点击 → 需求卡冻结 → 进度条（检索中 → 编排中 → 校验中 → 核算中）
5. 完成 → 方案页签：按天行程、ⓘ 溯源；成本页签：结构与计算轨迹；待核实页签；检索过程页签
6. 刷新 → URL 带 `plan` → 自动恢复状态与方案

## 4. 页面状态矩阵
| 页面/模块 | 初始 | 加载 | 空 | 运行 | 等待确认 | 成功 | 失败 | 恢复 |
|---|---|---|---|---|---|---|---|---|
| 需求卡 | 空槽位 + 必须确认角标 | 骨架屏 | — | 发送中禁用输入 | 完整度不足：按钮禁用 + 原因 | 槽位 + 角标 | 统一错误条（LLM_FAILED 等） | 按 convId 拉取 |
| 对话 | 引导文案 | 发送中气泡 | — | — | 追问选项按钮 | AI 追问 | 错误气泡，保留输入 | 本地不存历史（后端 M0 无消息读取接口 → 标注） |
| 方案面板 | 引导文案 | 骨架屏 | 未生成 | 分阶段进度 + 回退轮数 | — | KPI + 按天卡片 | 失败原因 + 重新生成；ORPHANED 专用文案 | 按 plan 查询 status → versions |
| 成本 / 待核实 / 轨迹 | 隐藏 | 随方案 | 「没有待核实项」 | — | — | 表格 | — | 同上 |
| 手动检索 | 表单 | 加载中 | 放宽建议 | — | — | 候选列表 + 漏斗 | PARAM_INVALID 靠近字段 | URL query |

## 5. 接口契约
见后端 `technical doc` 第七节；错误统一 `{"error":{"code","message"}}` → 前端 `AppError{code,message,userMessage,retryable}`。`retryable`：LLM_FAILED / INTERNAL / 网络错误为 true；409/404/400 为 false。Mock 与真实接口切换：**无 Mock**，开发即对接本地后端（`BACKEND_URL`）。

## 6. 实现方案
- 路由：App Router；工作台为 Client Component 边界（交互密集），外层 layout 为 Server Component
- 状态来源：后端为事实来源；URL 存 convId / plan / tab；Local Storage 仅存「最近会话」偏好
- 轮询：`usePlanTask` Hook，2s，`document.visibilityState` 隐藏时暂停，完成即停，失败退避
- 响应式：`lg:` 三栏 grid；以下单栏 + 底部分段切换
- 安全：前端无密钥；所有请求走同源 `/api` rewrite；模型/供应商错误只显示 `userMessage`

## 7. 验收标准
- 自动检查：`npm run lint && npm run typecheck && npm run test && npm run build`
- 真实联调：后端 `uvicorn` 在 8000，`PLANNER_MODE=heuristic`（无 Key 时）；E2E：`npm run e2e`
- 人工：1440 / 1280 / 768 / 390 四个宽度走完第 3 节流程；刷新后方案仍在；生成按钮连点只产生一个任务；Console 无报错

## 8. 风险与回退
- 后端无消息历史接口 → 刷新后对话区不恢复历史，只恢复需求卡与方案（已在界面标注）；后续加 `GET /conversations/{id}/messages`
- 真实模型不可用 → 手动编辑槽位走通闭环，抽取相关验收待 Key

## 增补（2026-09-07 晚）· 需求采集改为多轮引导式

**变化**：对话区不再一次性列出 3 个追问。每一轮 AI 先给 1–2 句「分析」（对客户需求的理解与风险点），再只展示**下一步最需要向客户确认的一个问题**；顾问答完自动进入下一问；排队问题用尽时请服务端重新分析（`POST /conversations/{id}/next-step`）；信息齐全时给出需求摘要和「确认需求卡并生成方案」按钮。

**交互细节**
- 单选槽位：点选项即提交；多选槽位（目的地 / 酒店档次 / 饮食禁忌）：勾选芯片后「确定」，可附「其它」自由输入；无选项槽位（日期 / 年龄 / 预算金额）：自由输入后确定。
- 每个问题都可「先跳过」，稍后在需求卡里补。
- 顾问在需求卡里手动改了当前正在问的槽位，视为已答并推进。
- 后端内部质量提示（如「模型未追问 dietary，系统已补上」）不再显示在对话区，只进浏览器 console。

**服务端配套**
- 选项原文入库前归一化（`services/slot_values.py`）：「两人总计」→ `total`、「高端温泉旅馆」→ `ryokan`、「10月15日」→ `2026-10-15`；不合法值返回 400 `VALUE_INVALID`，前端把该问题恢复为可答并提示。
- `services/guidance.py`：规则层保证一定有下一问（冲突优先 → 缺失按结构性优先级 → 必问三项），模型层负责顾问口吻的分析与问法；模型越界的问题（问已知槽位、给非法选项）被过滤；模型失败回落规则层。

**增补 · 生成失败后的回修路径**：当失败原因是「硬过滤后可用酒店不足」（`CANDIDATES_TOO_FEW`，检索是确定性的，不改条件重试无意义），方案区与对话区的按钮都变为「回到需求卡修改」：切到需求卡、滚动到并高亮相关槽位（从放宽建议文字识别档次 / 预算 / 日期，并并入需求卡冲突涉及的槽位）、直接打开第一个槽位的编辑框；改完点「重新生成方案」。其它失败（模型不可用、服务重启）仍提供「重新生成」。

**增补 · 视觉改版与侧栏功能（2026-09-08）**
- 视觉：按产品经理提供的仪表盘参考图改版——浅灰画布、白色大圆角悬浮卡、软投影、石板蓝主色、胶囊按钮/徽标/页签、圆形图标侧栏；Logo 仍用 BDT 富士山圆标；字体 Manrope（OFL 自托管）+ 系统中文字体。首页横幅使用 BDT 官网自有图片。
- 侧栏：默认 72px 图标态，悬停临时展开，点击可固定（偏好存 localStorage，用 useSyncExternalStore 读取避免 hydration 不一致）。内容：新建会话、工作台、手动检索、最近会话列表（状态点：采集中/已确认/生成中/已生成/失败 + 相对时间）、模型状态（提供方/模式/密钥是否配置，来自 `GET /api/v1/meta`）、帮助与说明弹窗。手机端顶栏「最近会话」按钮打开抽屉。
- 后端新增：`GET /api/v1/conversations?limit=` 会话列表（标题取首条顾问原话前 24 字，仅界面展示，不进模型）、`GET /api/v1/meta` 运行元信息（不含密钥）。
- 生成卡死防护：模型单次调用超时 120s（`LLM_CALL_TIMEOUT_SEC`）；状态查询时心跳超过 180s（`TASK_STALL_TIMEOUT_SEC`）的任务标记 `STALLED` 失败，前端显示「模型长时间无响应，任务已终止」并提供重新生成。

**增补 · 跳转体验（2026-09-08）**：外壳（侧栏 / 顶栏 / 页脚）移入根布局 `app/layout.tsx`，跨路由常驻不重建（会话列表、展开状态、模型状态不再闪烁）；内容层 `RouteTransition` 按 pathname 重挂并做 260ms 淡入上移；方案面板页签内容 200ms 淡入；原生 `<dialog>` 加 220ms 弹出与遮罩渐显；`prefers-reduced-motion` 下全部动效关闭。生成按钮在任务运行期间保持禁用（防连点、也避免对正在生成的方案重复提交）。实测切页 86ms，侧栏 DOM 节点在切页前后为同一节点。
